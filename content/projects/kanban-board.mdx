## System intent

Driftboard is a rebuild of an earlier, simpler Kanban project into a genuinely usable local-first planning tool. The constraint is the product: no accounts, no backend, no sync. The whole board lives in your browser, saves itself as you type, and works offline. Everything else is in service of making that feel fast and delightful rather than limiting.

It is a UI-systems project first. The interesting problems are drag ergonomics, keeping a rich board model clean under many mutations, and making undo, filtering, and cross-column moves coexist without turning component state into a swamp.

## Requirements

- Cards move within and across columns, and columns reorder, without corrupting order.
- The board survives refresh and works with no network.
- Every mutation is a typed store action so undo/redo is a byproduct, not a bolt-on.
- Search, quick filters, label filters, and sort are display concerns that never mutate stored order.
- A file can be exported and re-imported without ever corrupting the board.

The board model owns columns, cards, and labels. A Zustand store exposes typed actions (`moveCard`, `moveColumn`, checklist and label edits, and so on) and is wrapped by zundo for undo/redo and by a persistence layer that mirrors to `localStorage`. A separate, non-undoable UI store holds theme, density, focus, filters, and selection, so undoing a card move never rewinds your theme.

## Design decisions

**dnd-kit over the alternatives.** The earlier version used the archived `react-beautiful-dnd`. Driftboard moves to dnd-kit, whose `DragOverlay` decouples the moving card from list re-renders. That single choice removes the cross-column flicker the old approach fought, and gives a lifted preview and keyboard dragging for free.

**Commit once, on drop.** Cross-column dragging updates a temporary working copy for the placeholder, but the store is written exactly once when the card lands, so each move is a single, clean undo step.

**Filtering is a view, not a mutation.** Search, sort, and label filters transform what you see without touching stored order, and dragging is disabled while a filter is narrowing cards so rendered indices can never disagree with the model.

**Own your data.** The whole board round-trips to a zod-validated JSON file, so a bad import can never corrupt state and the board is trivially portable between devices.

## What I would improve

The next steps are a real mini-board preview on the landing page instead of a static snapshot, per-card multi-select drag, and an IndexedDB path for boards large enough to strain `localStorage`. The most valuable refinement is deeper keyboard support so the entire board, not just dragging, is operable without a pointer.
