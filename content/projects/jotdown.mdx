## System intent

Jotdown does for Apple Stickies what iTerm2 did for Terminal: it keeps the familiar shape and raises the ceiling. Notes are still small, borderless windows that float on the desktop, drag, resize, and color like Stickies. Inside each one, though, is a genuine markdown editor: headings, lists, quotes, dividers, links, and fenced code all render in place, and only the line under the cursor reveals its raw syntax.

The constraint that shapes the product is friction. A note must be one keystroke away, with no vault to open, no project to file it under, and no account to sign into. Everything the app gains in capability, it has to pay for in kept simplicity.

## Requirements

- A new note is instant: a menu bar click or `⌘N`, no setup, no navigation.
- Markdown renders live, Obsidian-style, revealing raw syntax only on the active line.
- Checkboxes are interactive, code blocks are syntax-highlighted, and links are clickable.
- Notes are true desktop stickies: borderless, movable, resizable, collapsible, and colorable.
- Every note is stored as a plain `.md` file, readable by anything, forever.
- The whole thing stays small enough to read in an afternoon.

## High-level design

The app is two halves joined by a deliberately tiny contract. A native Swift/AppKit shell puts one borderless `NSWindow` on screen per note, each hosting a `WKWebView`. The editor inside is CodeMirror 6 with a custom live-preview plugin that hides formatting tokens except on the lines the selection touches. When text, color, or a drag happens, the web view posts a small message; Swift moves windows and writes files. The editor never assumes the bridge exists, so the same page runs headless in a browser, which is what the parity test suite drives.

## Design decisions

**The document is the source of truth.** Interactive checkboxes, Quip-style list numbering, and rendered bullets change how markdown is *displayed*, never what is *stored*. A note must open correctly in any other markdown tool, so every note is mirrored as a plain `.md` file on disk alongside its internal JSON.

**Rendering lives in a web view, windows live in AppKit.** A borderless, movable, multi-window desktop app is exactly what native `NSWindow` is good at, and live markdown with real undo, IME, and syntax highlighting is exactly what a mature editor engine is good at. Jotdown uses each for its strength and keeps the seam between them to a handful of message types.

**Migrated from a hand-rolled editor to CodeMirror 6.** The first editor was a contenteditable engine; its undo and cross-line selection were the worst defects. Moving to CodeMirror bought native undo, real selection, IME, and a proper Lezer markdown parser, at the cost of learning its decoration and precedence rules. The custom live-preview plugin reproduces the per-line reveal on top of native editing.

**Polite by default, attention opt-in.** Notes sit at the normal window level and layer like any other window. Making all notes float was tried and reverted: unfocused notes sat on top of freshly opened windows from other apps. Pinning a single note above the rest is opt-in, per note, and persists across relaunch.

**Vendored editor bundle.** The CodeMirror bundle is built offline with esbuild and committed to the repo, so `swift build` and `make install` work with no Node installed and the app has no network dependency.

## What I would improve

Notarization and a universal build so the download runs without a Gatekeeper detour and on Intel Macs as well as Apple Silicon; note search and quick-open across all notes; and a "start at login" toggle so the menu bar item is always waiting.
