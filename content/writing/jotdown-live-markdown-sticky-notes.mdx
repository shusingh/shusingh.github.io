Apple Stickies is the app I reach for most and respect least. It is perfect for the first ten seconds of a note: a keystroke, a yellow square, some text, done. There is no vault to open, no file to name, no project to file it under. Then the note grows. You want a checkbox, so you type a dash. You want a heading, so you make a line ALL CAPS. You paste a snippet of code and it turns into proportional mush. The thing that made Stickies great, its refusal to ask anything of you, is the same thing that makes it a dead end the moment the note becomes real work.

Jotdown is my answer to that. The pitch is a single sentence: do for Stickies what iTerm2 did for Terminal. Keep the exact shape, small borderless windows floating on the desktop that you drag, resize, and color, and raise the ceiling underneath until it disappears. Inside each note is a genuine markdown editor with live rendering, clickable checkboxes, syntax-highlighted code, and real undo. The whole thing had to stay one keystroke away, or it would just be another heavy notes app pretending to be light.

## Keep the sticky, raise the ceiling

The discipline of the project is entirely about what I refused to add. No accounts. No sync. No vault, no sidebar, no file tree, nowhere to "organize." A note is created from the menu bar or `⌘N` and it is already on your desktop. That constraint is not a limitation I tolerated; it is the product. The second Jotdown asks you to decide where a note lives, it has lost to Stickies.

So every feature had to pass one test: does it add power without adding a decision? Live markdown passes, because you can ignore it and type plain text. Interactive checkboxes pass, because they are just `- [ ]` that happens to be clickable. A hover toolbar passes, because it appears only when you want it. A settings panel would have failed, so there isn't one.

## A real editor is not a text box

The core technical bet is that the two hard parts of this app want two different technologies, and the honest thing to do is use both.

A floating, borderless, multi-window desktop app is exactly what native `NSWindow` was born to do. Live markdown with real undo, proper text selection, IME input, and syntax highlighting is exactly what you should never hand-roll. So the shell is Swift and AppKit: it owns the windows, the menu bar, and the disk. The editor is CodeMirror 6 running in a `WKWebView`. They talk over one deliberately tiny message bridge, and that is the entire architecture.

Keeping the bridge small is what keeps the app honest. The web view never assumes the bridge exists; it guards every call. That sounds like defensive boilerplate, but it has a real payoff: the same editor page runs headless in a plain browser, which is how the parity test suite drives it without a Mac in the loop.

## Reveal only the line you are on

The feature that makes Jotdown feel like an editor and not a previewer is stolen, gratefully, from Obsidian: markdown renders in place, and only the line your cursor is on shows its raw syntax. Click a heading and it becomes `## Heading` so you can edit it; click away and it snaps back to a rendered heading. A checkbox is a real checkbox until you are editing its line, then it is `- [x]` again.

Under the hood this is a CodeMirror `ViewPlugin` that walks the parsed syntax tree and builds decorations: hide the `#` and the `**` and the backticks, replace `- [ ]` with a widget, tint the fenced code block. The rule for what stays visible is one line of logic: reveal the raw tokens only on lines the selection is currently on. Everything else follows from that. On blur, the selection touches nothing, so the whole note renders.

## The document is the source of truth

Every display trick in Jotdown, the clickable checkboxes, the Quip-style list numbering, the rendered bullets, changes how the markdown looks, never what is stored. This is the rule I was most stubborn about. A note is a plain `.md` file. It has to open correctly in any other markdown tool, today and in ten years, because the alternative is a proprietary archive that holds your notes hostage, which is the one thing Stickies and every heavier app get wrong.

So alongside its internal store, every note is mirrored as a plain `.md` file on disk. Delete a note in the app and the file goes with it. There is no lock-in, because there is nothing to be locked into: the files are just there, readable by anything.

## Polite windows, and attention you have to ask for

The least glamorous and most re-litigated part of the app is window behavior. My first instinct was to make notes float above everything, the way a sticky "should." I built it, used it for a day, and ripped it out. Floating notes are not helpful; they are rude. An unfocused note would sit on top of a window I had just opened in another app, demanding attention it had not earned.

So notes now sit at the normal window level and layer like any other window. If you want one note to stay on top, a checklist you are working through, you pin that single note, on purpose, and it persists across relaunch. Attention is opt-in and per note. That is the whole philosophy in one setting: polite by default, loud only when asked.

## What it took, and what comes next

The unglamorous truth is that Jotdown's first editor was a hand-rolled contenteditable engine, and its undo was broken in ways I could not fully fix. Migrating to CodeMirror 6 was the move that made everything else possible: real undo across splits and merges, character-precise cross-line selection, IME, and a proper Lezer markdown parser, all for free, in exchange for learning one library's decoration and precedence rules. Most of the "how do I add this feature" questions turned into "which CodeMirror primitive already does this."

What is left is mostly polish that meets the world: notarization and a universal build so the download opens without a Gatekeeper detour and runs on Intel Macs too, search across notes, and a start-at-login toggle. None of it changes the thesis. The thesis is that you can keep the sticky and still have a real editor, as long as you are willing to say no to everything in between.
